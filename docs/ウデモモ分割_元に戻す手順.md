# ウデモモ分割（2026-11-03）— 控えと、元に戻す手順

## 何が変わるか
- 部位の表（meat_parts）に `cost_group`（集計分類）の列を足す。
- 前からの「ウデモモ」の行は、**番号はそのまま**で名前だけ「ウデモモ（部位未分類）」にする。集計分類は「ウデモモ」。
- 「ウデ」「モモ」の行を新しく作る（集計分類は「ウデモモ」）。下限は部位ごとで、3つとも0kg（未分類の前の10kgも0kgに）。
- 棚卸の評価単価は部位ごとの最後の仕入単価。その部位に仕入が無い時はウデモモ全体の最後の仕入単価（2026-11-03 社長決定：分類すると、これからの棚卸の金額は動いてよい。確定済みの棚卸は確定時の単価のまま）。
- 目利きのラベル品名の読み替え（全業者共通の初期値だけ）を ウデ／モモ に付け替える。
  - ウデ：ウデ・ミスジ・ウデサンカク・トウガラシ　／　モモ：それ以外（ウチモモ・シンタマ・ランプ など）
- **塊・棚卸・締め・出数の記録は1件も書き換えない。**

## 控え（自動）
アプリが起動して分割する直前に、同じ処理の中で次の表を丸ごと写し取る。分割は1回だけ行う（「ウデ」「モモ」がもうあれば何もしない）。

`bk20261103_meat_parts` / `bk20261103_meat_part_aliases` / `bk20261103_meat_menu_map` / `bk20261103_meat_lots` /
`bk20261103_meat_stock_count_lines` / `bk20261103_meat_period_closings` / `bk20261103_meat_lot_events`

## 控え（手元、反映の前に）
`backup_db.py` で全部の表を CSV にできる（使い方はファイルの先頭に書いてある。URL はチャットに貼らない）。

## 元に戻す（分割した直後、まだ分類していない時）
PostgreSQL で次を実行する。部位の表と読み替え表だけを、控えのとおりに戻す。

```sql
BEGIN;
DELETE FROM meat_part_aliases;
INSERT INTO meat_part_aliases SELECT * FROM bk20261103_meat_part_aliases;
DELETE FROM meat_parts WHERE name IN ('ウデ', 'モモ');
UPDATE meat_parts p SET name = b.name, sort_order = b.sort_order, min_stock_kg = b.min_stock_kg, cost_group = NULL
  FROM bk20261103_meat_parts b WHERE p.id = b.id;
COMMIT;
```

あわせて、プログラムを分割の前（コミット 20b90a7）に戻す。プログラムだけ戻さずに表を戻すと、次の起動でまた分割される。

## 分類したあとで戻す時
ウデ・モモにした塊や、新しく入れた塊がある時は、上の手順だけでは足りない（ウデ・モモの番号が付いた塊が残る）。
その時は `bk20261103_meat_lots` と今の `meat_lots` を見比べて、1件ずつ決める。
